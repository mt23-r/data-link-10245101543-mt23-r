# M1 系统处理流程与风险说明

## 接口、通信与风险说明

1. 原始接口提供什么数据？

   `raw_states.json` 提供批次时间和 OpenSky 状态向量。课程使用目标标识、呼号、时间、经纬度、高度、速度、航向、垂直速度和地面状态等字段。

2. 为什么原始数据不是完整态势结果？

   原始数据只是分时观测，尚未按目标分组、按时间排序、选择最新状态并执行质量检查。

3. 为什么发送方需要把内部状态封装成消息？

   内部记录包含字符串、浮点数、布尔值和空值。封装为固定41字节帧后，双方才能按照统一偏移、字节序、定点规则、有效位和校验和交换数据。

4. 为什么接收方要检查长度、类型、校验和与保留位？

   长度和类型检查用于识别错帧，校验和用于发现损坏，保留位检查用于确认协议一致性。检查通过只表示课程帧格式有效，不代表来源真实可靠。

5. CSV 与 SQLite 分别承担什么角色？

   CSV是必做成果，用于人工检查和跨工具重读；SQLite是选做持久化方式，用于结构化查询和读写一致性验证。

6. 至少列出三个工程风险，并说明影响与处理方式。

| 风险 | 影响 | 处理方式 |
|---|---|---|
| 缺失值与真实0混淆 | 产生虚假位置或运动状态 | 使用`validity_flags`；无效字段恢复为`None` |
| 时间缺失或延迟 | 航迹乱序、当前态势过期 | 仅在位置时间为空时回退最近联系时间，并执行延迟检查 |
| 消息损坏或字节序错误 | 字段错位、物理量失真 | 固定大端和偏移，检查长度、帧头、校验和与保留位 |
| 量化或存储失败 | 精度超差或后续阶段无法读取 | 检查量程和往返误差，验证CSV和SQLite能够重新读取 |
